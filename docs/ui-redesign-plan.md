# EasyPaper 全站 UI 改版方案

状态：全站前端已按本方案改造，构建与交互回归已通过。日期：2026-09-10。

第 1 节记录改版前的观察；第 9 节记录最终实现和验证范围。视觉规范见根目录 `DESIGN.md`。

本方案按“阅读优先”规划：主要使用者希望完整读懂英文论文，整理、关联和复习帮助他保留理解。依据是 `PRODUCT.md` 的用户定义、现有页面和阅读功能。工作区采用新的视觉语言，完整 PDF 继续作为阅读主体。

## 1. 改版前的问题与证据

改版前的页面按处理步骤和数据类型组织，使用者需要自己推断“我现在能做什么”。首页首先要求上传和选择处理方式，回访时仍被大幅上传区占据；知识页面优先展示“实体”，论文发现及其证据藏在后面的标签页。更换组件外观无法独立解决这些问题。

| 问题 | 观察依据 | 改版决定 |
| --- | --- | --- |
| 回来后不容易继续读 | 桌面首页“最近文档”位于 y=607，首个继续阅读按钮 y=734；390px 手机上按钮 y=832 | 首屏先显示最近阅读的论文和继续按钮，导入缩为常驻入口 |
| 主要按钮没有视觉优先级 | Button 使用 `bg-primary` 等语义类，但 Tailwind 未配置对应颜色；实测继续阅读按钮背景透明 | 先补齐主题变量及 Tailwind 映射，再改页面 |
| 页面之间缺少明确路径 | 全局只有品牌、知识库和账户；图谱、复习依赖知识库中的入口 | 工作区提供“我的论文 / 知识笔记 / 复习”，知识区内进入图谱 |
| 功能名字偏实现 | 单篇详情默认“实体”；图谱展示类型代码和“重要性”百分比 | 先呈现发现和证据，术语改成“概念与方法”；模型分数退出主要信息层 |
| 移动端直接压缩桌面布局 | 在 390px 视口，单篇详情实际宽度 552px，图谱 425px；标题被挤成窄列 | 操作区换行、内容 `min-width: 0`，长标题可换行；图谱补可操作的列表视图 |
| 阅读器操作层堆叠 | 页面头、保存栏、PDF 工具栏各占一行；“论文提问”面板同时装概览 | 文档级操作一行，PDF 原生工具一行；右侧保留概览、批注；提问使用悬浮对话入口 |
| 保存与匹配容易被混淆 | 同一条状态同时报告服务器保存和跨版本匹配 | 两种状态分别表达，未匹配项可直接定位和重试 |

改版前的测量使用当时前端构建与隔离的固定示例接口，尺寸为 1440×1000、390×844。尺寸和样式缺陷已实测；阅读器判断来自现有组件和用户截图。本次测量不代表真实论文的翻译、问答或标注匹配质量。

代码入口：[Layout](../frontend/src/components/Layout.tsx)、[Dashboard](../frontend/src/pages/Dashboard.tsx)、[Reader](../frontend/src/pages/Reader.tsx)、[PaperDetail](../frontend/src/pages/PaperDetail.tsx)、[KnowledgeGraph](../frontend/src/pages/KnowledgeGraph.tsx)、[Tailwind 配置](../frontend/tailwind.config.js)。

## 2. 用户应该理解的能力

产品主张：**读懂一篇论文，把理解留在原文旁边。**

能力通过操作及其结果体现：

1. 导入 PDF 或论文链接，先打开可用的原文；生成译文时仍可阅读。
2. 在原文、中文、简化英文、双语对照间切换，保留阅读位置。
3. 不懂的内容就地提问；对照答案引用回到正文核实。
4. 高亮、下划线和笔记跟随相应内容；明确报告跨版本匹配结果。
5. 从读过的论文中整理发现、概念、个人笔记和复习卡，查看关联或导出。

首次使用页面用一小段明确标为示例的原文、译文与同色批注展示阅读方式。已经有论文后，不再反复展示介绍区。

## 3. 导航与页面关系

```text
工作区
├─ 我的论文                         /dashboard
│  ├─ 导入 PDF / 论文链接           对话框；手机全屏面板
│  └─ 阅读器                       /reader/:taskId
│     ├─ 原文 / 中文 / 简化英文 / 双语对照
│     ├─ 概览 / 批注                 同一个辅助面板，一次打开一项
│     └─ 问论文                      右下角悬浮对话框，自动关联当前论文
├─ 知识笔记                         /knowledge
│  ├─ 单篇知识                     /knowledge/paper/:paperId
│  │  └─ 发现与证据 / 概念与方法 / 我的笔记 / 复习卡
│  └─ 关联图谱                     /knowledge/graph
├─ 复习                            /knowledge/review
└─ 账户菜单
   ├─ 连接与导出设置                复用现有 Obsidian 配置能力
   └─ 退出登录

登录 / 注册                        /login、/register
旧摘要链接                         /summary/:taskId → 阅读器“概览”
```

“我的论文”包含导入的文件；“知识笔记”只包含已开始知识整理的论文。前者负责阅读，后者负责回顾阅读所得。未整理时给出“整理这篇论文”，不要求使用者重新导入。

桌面工作区使用约 208–224px 侧栏；阅读器独立铺满窗口。手机工作区使用紧凑页头和三项导航，账户放菜单。阅读器不出现工作区侧栏或底部导航。现有 URL 保留，返回列表恢复搜索条件和滚动位置。

## 4. 各页面布局与交互

### 4.1 我的论文

**回访首屏：** 页面标题与“导入论文” → 最近阅读 → 论文列表。

```text
导航 │ 我的论文                                  ＋ 导入论文
     │
     │ 继续阅读
     │ 论文完整标题                         [继续阅读 →]
     │ 中文译文 · 上次读到第 6 页
     │
     │ 全部论文                 按标题搜索…       状态筛选
     │ 论文标题 / 处理状态 / 上次位置 / 阅读操作
     │ 论文标题 / 处理状态 / 上次位置 / 阅读操作
```

- 默认列表，以标题及阅读动作作为对比依据。标题允许两行，辅助信息在下一行，避免每篇都成为功能按钮卡片。
- 继续区只取真实阅读记录；没有阅读记录则显示可读论文，不捏造阅读时长或完成百分比。
- 论文处理状态直接说“正在生成中文译文”“生成失败”“原文可读”，沿用后端实际阶段。失败行保留论文身份及重试入口。
- 同一行一个阅读主操作，概览和知识整理使用带文字的次操作；下载、重新处理、删除进入更多菜单。删除仍须确认。
- 无论文：显示简短能力示例及导入入口。搜索无结果：保留搜索词，提供清除筛选；不能显示“还没有论文”。
- 列表摘要只使用已有任务数据。若要显示各阅读版本的实时可用状态，应补轻量汇总数据，不能为每一行拉取整份阅读器数据。
- 列表和继续阅读优先显示原始 PDF 的标题元数据，未提供标题时显示原文件名；支持按两者搜索。已有文件自动适用，无需重新导入。标题读取使用文件变更缓存，不请求模型或解析整篇论文。
- 原文标题下增加较小的中文译名，使用单独的标题翻译请求，数据库按任务和原文标题缓存。列表先显示原文，最多同时请求两条缺失译名；失败时保留阅读操作并提供重试。已是中文的标题不重复显示译名；搜索同时匹配原文、中文和文件名。

### 4.2 导入论文

- 主体只保留“选择 PDF / 粘贴链接”，两者共用清楚的格式要求及错误位置。
- 结果选项用“生成中文译文 / 生成简化英文”，解释原文同时保留。其余版本可在阅读器中生成，不能承诺一次导入立即得到四份成品。
- AI 自动标注归入可选设置，不抢占上传动作。
- 上传、文件解析、译文生成分阶段呈现；只有服务返回进度时显示百分比。原文可读后显示“先读原文”。
- 关闭面板不取消已提交任务；处理中可在论文行继续查看状态。
- 保留当前文件大小限制、链接错误处理、失败重试和取消行为。

### 4.3 阅读器

**首屏：** 文档操作条 → PDF 工具栏 → 完整论文。打开辅助面板时，正文仍占最大面积。

```text
← 我的论文   论文标题    原文 / 中文 / 简化 / 双语   概览 批注   导出 ⋯
目录  缩放  手形/选择  PDF 原生批注工具             已保存 · 2 条待匹配
┌─────────────────────────────────────┬─────────────────┐
│                                     │ 概览 批注 × │
│           完整 PDF 页面              │                 │
│     文字 / 图表 / 公式 / 真实批注      │ 只展示当前任务   │
│                                     │ 答案引用可回正文 │
└─────────────────────────────────────┴─────────────────┘
```

- 工作区使用靛蓝操作色，论文批注继续使用用户选定的原色。导航选中态与正文高亮不共用一套语义。
- 版本具有“可阅读 / 待生成 / 生成中 / 生成失败”状态。未生成的版本提供生成操作，不呈现空白阅读区或暗示可立即切换。
- 原文与派生版的页数可能不同。位置切换继续使用现有原始页映射，不用同页码直接跳转。
- 历史修订、重新生成、完整归档、批注 JSON 导入导出、知识笔记入口集中到有文字的文档菜单；带批注 PDF 保留直接入口。
- 概览显示论文摘要/结构；批注显示高亮、划线、评论及匹配状态。提问移到右下角带书本标识的“问论文”气泡，打开独立对话框，自动使用当前论文全文；用户只需输入问题。
- 对话支持连续追问、失败重试、可移除的选文引用与原文页码跳转。收起后保留本次消息和草稿，切换论文或刷新后清空；桌面对话不改变 PDF 宽度。手机对话框避让软键盘。
- “已保存”只描述数据持久化；匹配状态按已存在的目标版本报告。尚未生成的版本不计为匹配失败。
- 点击“待匹配”直接筛选相关批注。每条可查看源位置、缺失版本并重试；无法精确定位时明确待匹配，不能把整段涂色作为成功提示。
- 断网显示本地待上传及数量；服务端冲突与匹配失败分别提供相应操作。按钮完成反馈必须来自实际结果。
- 桌面辅助面板建议 360–400px，可按剩余阅读宽度调整；当正文变得过窄时改为覆盖面板。手机一次显示正文或辅助面板，并保留返回正文及关闭动作。
- 不修改现有 PDF 引擎、标注坐标转换、投影缓存、版本 ID、持久化协议或算法来实现视觉改版。UI 布局变化不能触发额外的阅读器卸载重建。

### 4.4 知识笔记列表

- 标题下一句话说明“回看论文中的发现和自己的笔记”，随后直接展示论文。
- 列表和图谱通过知识区局部导航切换；复习有全局入口，避免在页面头再堆叠多组同等权重按钮。
- 保留标题搜索及整理状态；如果尚无内容，动作指向已有可读论文的整理操作。
- 多篇导出放列表工具栏的导出菜单。Obsidian 配置移入“连接与导出设置”，已配置后可从论文及批量操作处同步。
- 整理中、失败、完成分别呈现；打开单篇整理中的论文应持续刷新状态，不能用固定占位文案让用户自行刷新。

### 4.5 单篇知识

**首屏：** 论文标题 / 作者年份 → 继续阅读 → 发现与证据 → 其他资料。

- 默认“概览”：摘要与主要发现。每条发现旁显示来源页或原文入口；没有证据时明确“未提供来源”，不生成装饰性引用。
- “概念与方法”：保留实体、方法、数据集和关系；面向阅读者呈现名称、含义和论文中的用途。关系可切换列表或图谱。
- “我的笔记”：保留手工笔记输入与已有内容。阅读器中的 PDF 批注和知识笔记目前属于不同数据结构，必须明确区分；可以互相进入，不能假设已有统一笔记接口。
- “复习卡”：呈现问答内容和复习入口，保留既有卡片数据。
- AI 整理内容标注其来源性质，用户笔记保留作者语义。AI 给出的重要性分数不作为客观知识评级。
- 顶部次操作缩为“导出”菜单，容纳单篇 JSON、已有同步操作。长标题与操作区在窄屏上下排列，不互相挤压。

### 4.6 关联图谱

- 进入后回答“这些概念之间有什么关系”，节点选择面板显示名称、解释、关联条目和来源论文入口。
- 搜索框明确“查找概念名称”，沿用当前名称匹配行为；不暗示语义检索或跨论文问答。
- 节点颜色只表达已有类型，旁边保留类型文字；名称与来源优先于模型重要性分数。
- 桌面图谱与检查面板并列；手机默认可读的概念/关系列表，可切换图谱。工具栏换行，画布按容器尺寸绘制，缩放和重置保留可达入口。
- 空图谱提供“选择论文并整理知识”。这是已有能力的正确入口，不把用户送到无法发起整理的空页面。
- 关系连线只采用实际返回的数据；不能用示意线假装后端已经发现了跨论文联系。

### 4.7 复习

- 页头标明“复习”及本轮进度；卡片突出问题，来源论文可进入。
- 先显示问题，点击或键盘显示答案，然后评分并进入下一张。评分沿用当前 0/1/3/4/5 及对应标签，不因 UI 简化修改复习算法。
- 五个评分在手机上换行且触控区足够，不能挤成五个难点击的小格。
- 区分“没有到期卡片”和“本轮已完成”；提供回到论文或知识笔记的下一步。
- 当前到期接口按上限返回列表，若用其长度做计数，达到上限显示“100+”或仅标记有待复习，不把截断数量当总数。
- 评分提交失败保留当前卡及选择，允许重试；不提前显示已完成。

### 4.8 登录、注册与账户设置

- 登录/注册共用布局：一侧为简短阅读能力示例，一侧为表单。手机先一行价值说明，再进入表单。
- 示例使用同一段原文与译文，让使用者理解“可以完整阅读，遇到疑问再提问”。不展示虚构用户数、成功率或研究评价。
- 邮箱与密码都有可读标签；错误说明在相应输入旁，提交状态可识别。保留现有注册限制及服务端错误行为。
- 连接设置说明 Obsidian 路径属于服务运行环境，结果区展示成功、部分失败和具体可操作错误。
- 下载菜单按用途命名：带批注 PDF、知识备份 JSON、Obsidian 笔记、引用 BibTeX/CSL-JSON、论文表格 CSV；仍保留完整格式名。
- 模型配置和 API 凭证继续由服务端管理；本次 UI 不引入凭证展示或复制入口。

## 5. 视觉方向

采用“研究工作台”：清楚的目录、编号、页边关系，少量动作色，内容像文件而非广告卡片。论文是视觉焦点，辅助区域承担检索和操作。

| 元素 | 建议 | 原因 |
| --- | --- | --- |
| 背景与内容面 | 浅灰白工作区 `#F5F6F8`，白色内容面 | 用表面区分工具与论文，减少大面积装饰 |
| 文字 | 石墨色 `#202630`，次文字 `#606978` | 保证中英文标签和长标题可读 |
| 动作色 | 靛蓝 `#4C53D2`，低饱和浅色选中背景 | 统一导航、主按钮、焦点；区别于用户批注用色 |
| 状态色 | 完成绿、等待琥珀、错误红，并配文字 | 颜色表达实际状态，不作为随机卡片分类 |
| 字体 | 控件与知识内容用系统无衬线；PDF 保留原始字体 | 避免中英文两套界面气质及网络字体负担 |
| 字号 | 页面标题约 26px，内容 15–16px，辅助信息 13–14px | 缩小宣传标题，给标题和证据留空间 |
| 边界 | 控件约 8px 圆角，弹层约 12px；细分隔线，少阴影 | 用对齐和层级组织页面，避免卡片套卡片 |
| 动效 | 按下、复制、展开反馈约 150–200ms，支持减少动态效果 | 反馈动作结果；正文、公式、批注位置保持静止 |

颜色已经进入语义变量与 Tailwind 映射；实际值、组件和适配规则以代码及 `DESIGN.md` 为准。

方向比较：暖纸阅读桌可保持现有绿色气质，但对多页面操作层的组织帮助有限；机场信息板的稳定行与状态位置值得借鉴，但不采用缩写和票据装饰；图书展示墙会让封面挤占标题与继续阅读动作。选择研究工作台，是因为这里需要反复读同一批论文，而不是浏览封面商品。

## 6. Spell UI 的使用边界

[Spell UI](https://github.com/xxtomm/spell-ui) 提供可以拷贝和修改的组件代码，适合借鉴局部反馈。它不决定本产品的导航及页面结构。

| 参考组件 | 放在哪里 | 采用前的修改 |
| --- | --- | --- |
| Rich Button | 导入、继续阅读、提交问题 | 对接现有 Button 变体及主题，限制高光与阴影 |
| Badge | 可读、生成中、待匹配 | 状态必须配文字；不把所有类型都染成独立颜色 |
| Copy Button | 回答、引用、导出路径 | 等待复制成功后再显示完成；处理失败，不能吞错 |
| Label Input | 账户表单、导入链接 | 补齐 label 与 input 的关联，保留错误说明与自动填充 |
| Kbd | 确实实现的键盘快捷键提示 | 未实现快捷键不显示装饰性键帽 |
| Color Selector | 需要定制的批注颜色选择 | 复用阅读器已有颜色能力，保留用户色值和可访问标签 |

不在工作区使用滚动字幕、文字逐字入场、倾斜论文卡、持续光线及大面积动态渐变。它们会与论文文字、公式和标注争夺注意力。

兼容性：当前项目为 React 18 / Vite / Tailwind 3；参考仓库使用 Next / React 19 / Tailwind 4，并包含 Motion。应逐个移植所需样式与行为，不整体更换框架或引入参考站的分析、登录、付费等依赖。复制其代码时保留 MIT 许可要求。

## 7. 实现顺序与边界

这是一份覆盖全站的改版规格，以下是依赖顺序，不代表只交付首页。

1. 主题与通用组件：补齐语义颜色；统一按钮、输入、菜单、弹层、状态、标题和空状态。
2. 工作区导航、我的论文与导入：确定进入、继续、返回的路径，并保留任务行为。
3. 阅读器：压缩外层工具区，明确辅助面板及保存/匹配状态；沿用已验证的 PDF 和批注逻辑。
4. 知识列表、单篇详情、图谱、复习：重排信息，修复窄屏，连接证据及来源入口。
5. 登录注册、连接设置、各类导出与失败状态：使用相同组件及反馈规则。
6. 全路径检查：构建、现有测试、关键交互回归，使用桌面和手机截图检查实际布局。

可由现有接口完成：论文列表、导入、各版本阅读、提问、批注、知识整理、知识详情、现有图谱数据、复习及导出。

需要谨慎补充的数据或状态：列表上的版本汇总、真实阅读进度分母、准确到期总数、整理详情的状态刷新。没有相应数据时省略该展示或明确范围。批注与知识笔记统一查询、全文全库搜索、跨论文问答、协作空间、自动准确完成所有匹配，都不属于本次视觉改版已有能力。
