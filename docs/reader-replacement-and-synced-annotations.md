# PDF 阅读器与跨版本批注

阅读器使用 EmbedPDF，在原文、中文译文、简化英语和双语 PDF 之间共享批注。来源批注与各版本的文字位置分开保存；跨语言匹配失败时，已保存的来源批注仍可读取和导出。

## 使用方式

- 在任一版本划线、高亮或添加批注，保存后自动匹配其他当前版本。切换版本不需要手动触发同步。
- 工具支持高亮、下划线、删除线、波浪线、便签及手写。文字标记按目标 PDF 的实际文字绘制；不能直接重排的手写或形状以关联便签展示。
- 顶部状态分别表示服务器保存、正在匹配、部分匹配和保存失败。部分匹配保留已经确认的位置；在批注面板可重新匹配或手动选中目标文字关联。
- 给批注添加的回复跟随父批注的位置；父批注尚未匹配的版本保留待确认状态。
- “带批注 PDF”导出当前版本的原生 PDF 批注。备份功能同时导出论文存档和共享批注数据。

## 数据与保存

`ReaderDocument` 表示当前用户拥有的不可变原件，`ReaderTaskLink` 连接临时任务与文档。`ReaderVersion` 按内容指纹保存各版 PDF、字形索引和生成时记录的段落对应。重新生成产生新版本，已有存档仍保留。

`ReaderAnnotation` 保存来源对象、摘录、修订、几何修订、删除状态及各版本的位置。颜色、批注正文等样式修改不会用目标版本坐标替换来源。`ReaderOperation` 保存操作回执，避免网络重试重复创建批注。

浏览器先把操作写入 IndexedDB，收到服务器回执后才移出待发送队列。刷新或网络恢复后继续发送。修订号检测并发修改，发生冲突时保留本地操作；较旧的轮询结果不能覆盖已经确认的新状态。删除采用可恢复记录。

尚未上传的浏览器存储被清除，或数据库与存档同时丢失且没有备份时，无法恢复。首次加载完整应用仍需要网络；这里未提供离线 PWA。

## 文字范围与匹配

保存时先收紧过高的文字框，避免 PDF 字体框覆盖相邻行。精确选区保持原坐标；无法确认的片段保留来源数据。

跨版本匹配依次使用不可变页面对应、生成时记录的段落对应和语义匹配。目标必须引用目标 PDF 中实际存在、能唯一定位的文字；位置由目标字形计算，模型不能直接指定矩形。双语页上的相同内容直接使用页面对应。

短选区的语义请求提供源句子和候选文本，要求返回细分的短语对应表，不向该请求提供用户选区边界。本地再按源选区筛选：

- 两侧摘录必须逐字存在，源摘录必须能消除位置歧义。
- 跨到未选中内容的对应会被拒绝，不能把整句套到几个选中的字上。
- 语序变化允许不连续的源或目标短语；同一段源文字不能重复支持不同目标内容。
- 数值、否定和未覆盖的限定词分别检查；有位置不等于完整匹配。
- 连接词不能单独支持一段动作或名词。仅在两个 PDF 都有紧邻已核验短语的对应连接词、且源连接词确实被选中时补入。
- 截断英文单词的单个字母不会自动扩成整词或下一句；完整部分继续同步，截断部分保留待确认状态。

例如，选中“电池耗尽”不应把相邻的“设备停止运行”一起标出。若缓存只包含两者组成的整句对应，新选区需要重新获得更细的证据。

明确的人工关联优先。已审核的范围在后台恢复时保留，用户主动重新匹配或修改来源范围时才重新计算。

## 同步耗时与复用

原文与其他目标版本尽量并行处理，每个已完成版本立即保存和显示，不等待所有版本结束。新标注优先于旧的部分匹配恢复；仅剩截断字母且当前版本已有对应的记录不反复占用模型请求。

模型单次响应期限从共享请求池允许执行后开始，排队时间不计为一次响应失败。单次响应期限为 20 秒，单条批注进入处理后总期限为 45 秒；超时保存已有匹配并显示可重试状态。

`ReaderPhraseAlignment` 持久保存经检查的句子短语表和完整选区结果，同句不同选区可按字符位置直接筛选。相同句子的并发请求合并，服务重启后缓存仍可复用。缓存按用户所属文档、源句子、目标文字和字形坐标隔离，每篇最多 256 条；内存另保留最多 128 个完整选区结果。

部分结果不进入完整选区缓存。新选区切断旧短语、PDF 改版或用户明确重新匹配时，需要新的对应证据。显式重试使旧缓存失效，已有缓存的旧请求不能覆盖重试失效标记。

有父批注的回复直接继承父批注位置，不把便签图标下的文字当作独立语义选区；父批注更正后更新已有回复。来源批注与回复正文不因匹配结果改变。

首次匹配仍受所配置模型的响应速度及语义准确率影响。模拟测试通过不代表任意新选区都能在固定时间内正确匹配。

## 存储与部署

数据库沿用 `DATABASE_URL` 或应用数据库配置，启动时创建新增表。PDF 存档位置依次取：

1. `EASYPAPER_READER_LIBRARY_DIR` 环境变量。
2. `storage.library_dir` 配置。
3. `<storage.temp_dir>/reader-library`。

两份 Docker Compose 均提供 `backend-library:/app/reader-library` 持久卷。数据库与完整存档目录必须一起备份，迁移时保留账户和目录关系，或使用同账户、同原件的 ZIP 导入。不要通过删除数据卷排查同步问题。

ZIP 导入校验账户、论文指纹与文件内容，不直接把归档路径解压到文件系统。压缩文件限制为 128 MB，解压后限制为 512 MB。跨账户迁移及任意历史操作回滚不在当前界面范围内。

PDF 生成使用进程内后台任务；服务重启后中断的生成被标为可重试，已有文件不回退。默认部署使用单个应用 worker，未引入分布式任务队列。

真实配置、API 密钥、数据库、PDF 存档、日志和本地开发工具状态不进入源码仓库。配置示例只包含占位符，部署者应自行设置凭据。

## 验证

后端回归覆盖四版本投影、跨行选区、范围扩张拒绝、重复文本消歧、数字与否定、缓存隔离和重启、并发与显式重试、回复继承、保存去重、陈旧修改冲突、样式共享、删除恢复、模型失败、人工关联、版本生成及备份恢复。

前端测试覆盖来源原生 ID、多个投影共享 ID、持久队列、账户隔离、过期服务器响应以及字形定位。浏览器测试使用独立临时数据库和构造的 PDF，验证绘制、切换与导出、刷新、断网恢复、多客户端冲突、手写、撤销、手机布局及备份导入。

导出的批注使用 PyMuPDF 独立检查。PDFium 写入期间，导出等待待提交操作清空并核对实际批注 ID，防止下载缺少标记的文件。需要检查精确文字范围时，使用标记内的字形中心，避免文本框提取包含相邻行。

当前检查包括 208 项后端测试、20 项前端测试和 5 项生产构建浏览器流程。浏览器测试的模型使用可控替身；实际模型的语义准确率需要另外验证。

```sh
# 项目根目录
PYTHONPATH=backend backend/.venv/bin/pytest backend/tests -q

# 前端目录
cd frontend
npm ci
npm run type-check
npm run lint
npm test
npm run build
READER_TEST_PRODUCTION=1 npm run test:reader
```

`test:reader` 自动启动并关闭独立的测试服务，需要后端虚拟环境与 Chromium。macOS 可使用已安装的 Google Chrome；其他环境设置 `READER_CHROME` 或运行 `npx playwright install chromium`。未验证实体触控笔、Safari 或大篇幅扫描论文。
